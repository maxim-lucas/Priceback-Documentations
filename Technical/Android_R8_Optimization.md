# Android R8 optimization (Play Console "App optimization" score)

**Date:** 2026-07-30 · **App version at change:** 2.8.1 · **Expo SDK 55 / RN 0.83.6**

## The problem

Play Console → App optimization reported:

| Metric | Value |
| --- | --- |
| Optimization | Low |
| Optimization percentage | – |
| Obfuscation percentage | 2 % |
| Shrinking percentage | – |
| R8 configuration | – |

## Root cause

The Android project is **generated by `expo prebuild`** (`android/` is gitignored), and the
Expo SDK 55 template leaves code shrinking off by default. In the generated
`android/app/build.gradle`:

```groovy
def enableMinifyInReleaseBuilds = (findProperty('android.enableMinifyInReleaseBuilds') ?: false).toBoolean()
...
release {
    def enableShrinkResources = findProperty('android.enableShrinkResourcesInReleaseBuilds') ?: 'false'
    shrinkResources  = enableShrinkResources.toBoolean()
    minifyEnabled    = enableMinifyInReleaseBuilds
    proguardFiles getDefaultProguardFile("proguard-android.txt"), "proguard-rules.pro"
}
```

Neither property was set anywhere, so **R8 never ran** on release builds. The 2 %
obfuscation Play measured was only third-party AARs that ship pre-obfuscated.

Note the property is `android.enableMinifyInReleaseBuilds` in SDK 55 —
`android.enableProguardInReleaseBuilds` is the deprecated older name and is ignored
by this template.

## The fix

Added `expo-build-properties` (`~55.0.13`) as the first entry in `app.json` → `expo.plugins`:

```jsonc
[
  "expo-build-properties",
  {
    "android": {
      "enableMinifyInReleaseBuilds": true,
      "enableShrinkResourcesInReleaseBuilds": true,
      "extraProguardRules": "..."   // see below
    }
  }
]
```

`enableShrinkResourcesInReleaseBuilds` **requires** `enableMinifyInReleaseBuilds`;
the plugin throws at config time otherwise.

### Extra ProGuard rules

Most native modules in this app ship their own consumer rules and need nothing added
(verified present: `expo-modules-core`, `expo-notifications`, `expo-updates`,
`react-native-reanimated`, `react-native-worklets`, `react-native-svg`). Only the gaps
are covered explicitly:

```proguard
# Keep crash reports readable after R8 renaming (Sentry uploads the mapping file).
-keepattributes SourceFile,LineNumberTable,*Annotation*,Signature,InnerClasses,EnclosingMethod,Exceptions
-renamesourcefileattribute SourceFile

# React Native bridges these reflectively from JNI / the TurboModule registry.
-keep,includedescriptorclasses class com.facebook.jni.** { *; }
-keep class com.facebook.react.turbomodule.** { *; }
-keep class com.facebook.hermes.unicode.** { *; }

# RevenueCat models are (de)serialized reflectively and ship no consumer rules.
-keep class com.revenuecat.purchases.** { *; }

# Sentry looks up integrations by class name.
-keep class io.sentry.** { *; }
```

These land in `android/app/proguard-rules.pro` inside an
`# @generated begin/end expo-build-properties` block on every prebuild.

### Sentry mapping upload (required alongside R8)

Without this, every Java/Kotlin stack trace in Sentry becomes unreadable once R8
renames classes. The `@sentry/react-native/expo` plugin only applies the Sentry
Android Gradle Plugin when explicitly asked, so `app.json` now passes:

```jsonc
[
  "@sentry/react-native/expo",
  {
    "organization": "prosoft-inc",
    "project": "priceback-canada",
    "experimental_android": { "enableAndroidGradlePlugin": true }
  }
]
```

This injects `io.sentry:sentry-android-gradle-plugin:5.12.2` and a `sentry { … }`
block with `includeProguardMapping = true` and
`autoUploadProguardMapping = shouldSentryAutoUpload()`. Upload is gated on
`SENTRY_AUTH_TOKEN` being present, so builds without the token still succeed — they
just skip the upload.

## Verification done

`npx expo prebuild -p android --no-install` regenerates:

- `android/gradle.properties` → `android.enableMinifyInReleaseBuilds=true`,
  `android.enableShrinkResourcesInReleaseBuilds=true`
- `android/app/proguard-rules.pro` → the generated rules block
- `android/build.gradle` → `classpath("io.sentry:sentry-android-gradle-plugin:5.12.2")`
- `android/app/build.gradle` → `apply plugin: "io.sentry.android.gradle"` + `sentry { … }`

A local release build was **not** possible on this machine (no JDK on PATH, and

## iOS impact: none (verified against plugin source)

Both edits are Android-scoped by construction:

**`expo-build-properties`** — only an `android` key is passed. Its three iOS hooks
(`node_modules/expo-build-properties/build/ios.js`) resolve to nothing:

| Hook | Behaviour with no `ios` key |
| --- | --- |
| `withIosDeploymentTarget` | early-returns — `props.ios?.deploymentTarget` is undefined |
| `withIosInfoPlist` | early-returns — `reactNativeReleaseLevel` is undefined |
| `withIosBuildProperties` | every getter returns `undefined` except two constants (below) |

The two constants written into `ios/Podfile.properties.json` are inert:

- `EX_DEV_CLIENT_NETWORK_INSPECTOR="true"` — already the default
  (`expo-dev-launcher.podspec` enables it *unless* the value is exactly `'false'`),
  and the code it guards is `#if DEBUG`-gated, so release builds are unaffected.
- `apple.privacyManifestAggregationEnabled="true"` — no consumer exists anywhere in
  this project's `node_modules` at SDK 55; it is read by newer Expo Podfile logic only.

Notably `ios.useFrameworks` is **not** written, so the CocoaPods modular-headers
workaround in `plugins/withIosModularHeaders.js` (commit `13e2e3f`) is untouched, as is
`plugins/withIosPrivacyStringCleanup.js`.

**Sentry `experimental_android`** — `withSentry.js` calls
`withSentryAndroidGradlePlugin` only inside `if (props?.experimental_android && …)`.
`withSentryIOS` receives the unchanged `sentryProperties` string, which is derived
solely from `organization` / `project` / `authToken` / `url`. The iOS Sentry setup is
byte-identical.

`npx expo prebuild -p ios` cannot run on Windows ("Run `npx expo prebuild` again from
macOS or Linux"), so this is a source-level analysis rather than a generated-project
diff. The next macOS/EAS iOS build is the empirical confirmation.

## Still owed — device smoke test before production

R8 can break reflection-dependent code at runtime, not at build time. Before promoting
this to the production track, build `eas build -p android --profile preview` (release
buildType, APK) and exercise on a real device:

- Google Sign-In and Sign in with Apple
- RevenueCat paywall + purchase restore
- Camera / document scanner (receipt + price-tag scan)
- Push notifications and background fetch
- expo-updates check
- A deliberate JS + native error, confirming Sentry symbolication still resolves

## Not actionable: "Upgrade to AGP version 9.0"

Play's recommendation cannot be followed independently. AGP is pinned by React Native
at `agp = "8.12.0"` in `node_modules/react-native/gradle/libs.versions.toml`; the
Gradle wrapper is 9.0.0. Moving to AGP 9 requires an upstream RN/Expo release that
supports it. Revisit at the next Expo SDK bump.
